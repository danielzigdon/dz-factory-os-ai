# 24 — Website → S02 quote-intake contract (IMP-05, DRAFT)

**Status:** draft proposed by Claude. It needs ChatGPT approval in [doc 23](23-improvement-dialogue.md). It is a specification only. **No code, no endpoint, and no Sprint 1 work.** It turns [doc 19](19-public-website-spec.md) §"קליטת פניות" and WEBSITE-REVIEW-01 finding 5 into testable criteria for the sprint that will eventually build intake (per doc 05, AC1.6).

## 1. Flow
```
Browser form (public site, separate app per doc 19)
  → POST https://<site>/api/quote   (site server; same origin; no third parties)
      validates, rate-limits, spam-checks, strips HTML
  → POST <crm>/api/intake           (server-to-server, HMAC-signed, AC1.6)
      normalises + A-01 dedupe → lead (source=website) in S02
```
The browser never calls the CRM or Priority directly. **Priority is never written** by intake (A-04/A-06).

## 2. Fields (match the current Preview form)
| Form field | id | Required | Server rule | Lead field |
|---|---|---|---|---|
| שם מלא | `customer-name` | yes | 2–80 chars, plain text | `contact_name` |
| שם החברה | `company` | no | ≤ 120 chars | `company_name` |
| טלפון או אימייל לחזרה | `reply` | yes | Exactly one valid phone (E.164 `+972…`) **or** e-mail. Otherwise 422 | `phone_normalized` / `email_normalized` (A-01) |
| חומר הגלם | `material` | no | One of the listed options | `details.material` |
| כמות משוערת | `quantity` | no | ≤ 60 chars | `details.quantity` |
| כמה מילים על העבודה | `description` | yes | 10–2000 chars, HTML stripped | `details.description` |
| (hidden) consent | `privacy_ack` | yes | Must be `true`. The consent text version is stored | `consent_version` |
| (hidden) honeypot | `website` | must be empty | Non-empty → silent 202 and discard | — |

- **Attachments are out of scope** until a storage and malware-scan decision exists.
- **Marketing consent** is separate and optional. It is never a condition for submitting (doc 19). WhatsApp contact stays blocked until Q-10.

## 3. Server rules
- **Site `/api/quote`:**
  - Rate limit 5 requests per IP per 10 minutes and 50 per day, with 429 and a `Retry-After` header.
  - Body ≤ 16 KB.
  - JSON only.
  - CSRF: same-origin check plus an `Origin` header allow-list.
- **CRM `/api/intake`:**
  - `X-Signature: sha256=HMAC(secret, timestamp + "." + body)`.
  - Reject a timestamp skew over 5 minutes (401).
  - Reject a replayed `source_event_id` (UNIQUE → 200 idempotent, no second lead).
- **Lead data:**
  - `source=website`.
  - `source_event_id` is a UUID generated by the site.
  - `status=NEW`, unassigned.
  - The SLA clock starts at receipt (A-09).
- **Dedupe:** A-01 M1–M4 unchanged. A phone or e-mail match only produces a *suspected* duplicate, never an automatic merge or link.
- **Logs:** no message body and no full phone or e-mail in application logs. Keep the IDs only.

## 4. User-visible behaviour
- **Success:**
  - The message says "הפנייה התקבלה; נחזור אליכם בשעות הפעילות".
  - There is no promise of a response time until Daniel approves one.
  - Focus moves to the result region, as in the current Preview.
- **Rate-limited:** a polite Hebrew retry message.
- **Server error:** a message showing the phone number, with no stack trace.
- **Field errors:** the current inline, accessible validation is kept.

## 5. Acceptance tests (for the future sprint)
1. A valid submission creates exactly one lead with `source=website` (S02 shows it as "חדש", unassigned).
2. The same `source_event_id` sent twice still yields exactly one lead.
3. A bad or missing HMAC → 401. A stale timestamp → 401. 6 posts in 10 minutes → 429.
4. A filled honeypot → 202 and no lead.
5. A phone matching an existing customer → `customer_match=suspected`, with no link.
6. No request to Priority or third-party hosts during the flow (network log).
7. `privacy_ack` missing → 422.
8. axe 0 on the form in every state at 320–1440.
